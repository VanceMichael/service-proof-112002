# 跨区送达回执的事实接收与补送授权的演练来源

这里提供独立来源的本地合成记录，与实际单位、个人和线上业务无关。

## 本地运行

使用 Node.js 22.23.4。只使用 Node.js 自带的运行库。

执行 `npm test` 检查合成来源的接口。执行 `npm start` 启动来源，默认监听 `127.0.0.1:4100`，可通过环境变量 `PORT` 调整端口。访问根路径可看到来源名和当前回放阶段。

## 接口资料

| GET 路由 | 来源约定 |
| --- | --- |
| `/source/clerk` | parties 是受理系统身份。文书具有 edition。同一案件以明确的当地日历和当地时间起算，期限按送达日后五个工作日。 |
| `/source/delivery` | posted 不证明到达。signed 指门房或代理签收。bag 可装多个通知，不用它替代逐件证明。 |
| `/source/electronic` | opened scope=封面不足以作为文书确认，manifest 确认该袋内具体对象。 |

查询参数 `offset` 是从零开始的页偏移，`limit` 默认 3，取值 1 至 100。响应中的 `records` 含 `record` 来源记录键、`availableFrom` 首次出现的回放阶段、`kind` 记录类型、`payload` 业务字段。来源记录键与业务身份分别定义。`next` 为下一页偏移，末页为 `null`。回放阶段中的记录按到达顺序可查。

控制员通过 `POST /control?stage=2` 切换到第 2 阶段，服务会保留更早已可查的记录。每次换阶段后按根路径返回的 `stage` 确认切换成功。

## 送达工作台

`npm run workbench` 连接本地来源（默认 `http://127.0.0.1:4100`），按回放阶段逐段从受理门户、承运方、电子服务站取得记录，输出承办人工作台：可补送清单、已生效且不再自动补送的项目、待人工裁决的冲突回执、补送单状态、期限通知追踪、实际未送达清单与送达台账。

参数：`--source` 来源地址；`--today` 工作台参考日（默认当天，用于挑选当前有效地址）；`--through` 回放到的阶段；`--snapshot` 将推导结果导出为 JSON。

推导规则（`src/engine.mjs`）：posted 只证明交寄；门房签收须与同一主体的清单回读合成一次送达，本人逐件确认独立成立；送达事件按登记联系信息的当地时区取本地日期，代理资格按该日期核验；同一文书版本对同一主体只存在一份生效义务，由已证实有效的最早送达决定首次期限（送达日后五个工作日，节假日不计入）；已通知的答复窗口不被系统自动缩短，冲突交人工裁决；补送单只增不删，未寄出的可停止，已交承运的显示待撤或无从撤回。
